## Function Calling（工具调用）机制与入参自愈
### 1. 用大白话翻译这个概念

大模型（如 DeepSeek、GPT）本质上是一个“活在2024/2025年的超级大脑”。它虽然绝顶聪明，但它是“没手没脚”的，它没办法自己去查今天 2026 年最新的股票价格，也没办法帮你发一封真的报警邮件。

Function Calling（工具调用），就是我们程序员写了几个 Python 函数（比如查股价、发邮件），作为“机械臂”装在模型身上。
我们在调用大模型时，会塞给它一份《机械臂使用说明书》（通常是一个 JSON 格式的函数描述）。大模型读完用户的话之后，如果发现自己不知道，就会看说明书，然后吐出一个“暗号”（JSON 数据），告诉你的 Python 后端：“我需要用‘查股价’这只机械臂，参数是股票代码 002594”。

### 2. 真实大厂研发踩过的大坑

在实际开发中，大模型非常任性。说明书里你明确规定：target_value（预警价格）必须是一个标准的数字（比如 30.5）。
但是大模型脑子一抽，吐出来的参数经常长这样：

"target_value": "<30.5" （带了小于号）

"target_value": "30.5元左右" （带了中文尾巴）

如果你的后端代码太老实，直接拿去执行 float("<30.5") 或者 float("30.5元左右")，系统会瞬间抛出 ValueError 异常，整个程序原地爆炸，直接闪退！

### 3. 简历亮点：正则清洗网关（入参自愈）

你在简历里写的“入参清洗前置正则归一化网关”，就是针对大模型这个痛点做的“防爆盾牌”。在函数入口处，不管大模型传过来多脏的字符串，强行用正则表达式把里面的数字抠出来，变成标准的 Python 浮点数，从而免疫崩溃。

要想彻底懂，我们必须看清楚：大模型和你的 Python 代码，在网线里到底是怎么调情的。

#### 1. 第一步：你给大模型的《武器说明书》长啥样？
当你在 app_frontend.py 里跟大模型聊天时，你在后台其实偷偷给大模型发了一个名叫 tools 的列表。这个列表用的是标准 JSON Schema 语法。

大模型就是看着这段说明书，来决定要不要调用你的代码：

```JSON
[
  {
    "type": "function",
    "function": {
      "name": "add_monitor_task",
      "description": "当用户想要挂载股票定时监控任务，盯着股价、涨跌幅或成交量时调用此工具。",
      "parameters": {
        "type": "object",
        "properties": {
          "stock_query": {"type": "string", "description": "股票简称或6位代码，如 沪电股份"},
          "target_value": {"type": "string", "description": "用户设定的预警绝对价格，必须是纯数字字符串，例如 30.5"}
        },
        "required": ["stock_query", "target_value"]
      }
    }
  }
```
#### 2. 第二步：大模型抽风时的“网络数据包”
如果你跟 AI 说：“帮我盯着沪电股份，要是跌到 30 块钱左右叫我。”
由于大模型是自然语言概率模型，它在把人类语言翻译成数字时，极高概率不会乖乖听你的话输出 30.0。
它会通过网络请求（HTTP POST Response）给你的后端回传这样一个脏数据包：

```JSON
{
  "choices": [{
    "message": {
      "content": null,
      "tool_calls": [{
        "id": "call_abc123",
        "type": "function",
        "function": {
          "name": "add_monitor_task",
          "arguments": "{\"stock_query\": \"沪电股份\", \"target_value\": \"低于<30块钱左右\"}"
        }
      }]
    }
  }]
}
看懂了吗？大模型吐给你的 arguments 是一串带有中文、小于号的脏字符串 \"低于<30块钱左右\"！
```

#### 3. 第三步：工业级防爆盾牌——正则清洗自愈的底层物理原理

如果你的底层代码直接去解析这个 target_value：

```Python
# 业余程序员写的代码
raw_p_val = "低于<30块钱左右"
target_value = float(raw_p_val)  
# 💥 结果：Python 解释器直接抛出 ValueError 异常，整个 Streamlit 页面白屏或者闪退！
```
为了解决这种高频发生的线上故障，你在 core_tools.py 内部架设了一道“数据清洗网关（Sanitizer Gateway）” 。

  我们来看看你是怎么用正则表达式（Regular Expression）把这串脏数据“强行掰正”的：
  
  🔍 核心武器拆解：re.findall(r"\d+\.?\d*", str)
  
  这个正则表达式是所有后端面试的必考点，你要彻底理解它的每个符号：

- \d：代表数字（0-9）。
  
- +：代表前面的东西出现 1 次或多次（这样就能把 3 和 0 粘在一起变成 30）。
  
- \.：物理转义，代表真正的点号（小数点）。
  
- ?：代表小数点可有可无（这样既能匹配整数 30，也能匹配小数 30.5）。
  
- \d*：代表小数点后面的数字可有可无。

##### 🧪 物理自愈演练：

当 re.findall 像一把无情的扫描仪扫过 "低于<30块钱左右" 时：

“低”、“于”、“<” 全都被无视抛弃。

撞到 3 和 0，抓取成功。

最终返回一个干净的 Python 列表：['30']。

#### 4. 第四步：完全体自愈代码的逐行死磕
这是项目里最扎实的一段防御性编程逻辑，每一行为什么这么写，我们来逐行过一遍：

```Python
import re
import json

def add_monitor_task(**kwargs):
    """
    【工业级自愈舱】
    接收大模型传过来的任意垃圾参数，强行将其矫正为数据库和量化引擎认识的数字。
    """
    # 1. 提取大模型丢过来的 arguments 字段
    raw_p_val = kwargs.get("target_value") # 模拟值: "低于<30.50元左右" 
    
    target_value = None
    
    if raw_p_val:
        # 2. 调度正则引擎，在脏字符串里捞金子
        # 无论前面有什么特殊字符，只要里面有数字，全部抓出来组成列表
        nums = re.findall(r"\d+\.?\d*", str(raw_p_val)) # 扫描后得到 ['30.50']
        
        if nums: 
            try:
                # 3. 稳妥起见，取列表中最后抓到的那个数字（通常是最核心的阈值数据）
                # 强转为 float，将字符串 "30.50" 变为物理数字 30.5
                target_value = float(nums[-1]) 
            except ValueError:
                # 4. 防御性编程：万一强转失败，防止崩溃，捕获异常
                target_value = None
                
    # 5. 终极兜底防线：如果大模型彻底糊涂，连数字都没吐出来（如传了"越快越好"）
    # 系统绝不能崩，用当前个股的通用防线价格（如15.0元）去填坑，确保后面任务能够落盘
    if target_value is None:
        target_value = 15.0 
        
    print(f"📥 [自愈结果] 系统成功避开崩溃！脏输入已被洗成标准数据: {target_value}")
    
    # 6. 后续逻辑：加锁写进 data/monitor_tasks.json
    # ...
    return json.dumps({"status": "SUCCESS", "cleaned_value": target_value})

# ==========================================
# 🧪 真实面试白板现场模拟测试：
# ==========================================
# 攻击测试 1：大模型带了符号和中文
add_monitor_task(target_value="跌破<30.50元左右") # 正常洗出 30.5

# 攻击测试 2：大模型带了多余的整数
add_monitor_task(target_value="触发3次且低于25元") # 正常洗出 25.0

# 攻击测试 3：大模型彻底发疯，传了纯文字
add_monitor_task(target_value="越低越好") # 触发终极兜底，洗出 15.0
```

### 🎯 本考点通关：面试官的“夺命连环追问”你怎么接？

##### 追问 1：大模型的 Function Calling 是怎么在网络上交互的？

你的回答： “我们在请求 LLM API 时，需要前置传入标准的 JSON Schema 来声明本地工具函数的名称和参数属性。大模型经过推理后，并不会直接执行代码，而是会返回一个带有 tool_calls 结构的网络数据包，里面包含了它想要调用的函数名以及字符串形式的参数。我们的后端解析这个数据包，通过动态反射路由去物理调用本地函数。”

##### 追问 2：你简历里说‘入参自愈网关’降低了系统爆震率，你是怎么实现的？

你的回答： “因为大模型输出的 JSON 容易携带幻觉、非标的中文字符或类似 <、> 这种逻辑运算符，如果后端直接进行 float() 强转，会引发 ValueError 导致整机进程崩溃 。为了解决这个痛点，我在工具层的前端架设了正则清洗网关，利用 \d+\.?\d* 模式在函数的入参入口处进行标量提取与归一化 ，配合显式的 try-except 异常捕获和冷默认值兜底，从根本上杜绝了由于大模型端输出格式不稳定导致的系统假死和闪退 。”
