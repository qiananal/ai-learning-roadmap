## 补充考点 2：智能体系统性评估（Agent Evaluation）

### 1. 为什么我们需要自动化评估？（人工改卷的痛苦）

在你的 AxiomFin（金融盯盘）或 GAMUT（多模态质检）项目中，你做了很多优化（比如写了更好的 Prompt、重构了 RAG 检索）[cite: 29, 31, 35, 43]。
但是，大模型每天的输出都是不一样的。你今天改了一个 Prompt，怎么证明它确实变聪明了，而不是“改好了这 5 个问题，却改坏了另外 50 个问题”？

笨办法（人工评估）：自己写 100 个问题，每天手动测一遍，拿肉眼一条条看。不仅累死人，而且打分标准很主观（今天心情好给 $90$ 分，明天累了给 $60$ 分）。

旧办法（BLEU / ROUGE 自动打分）：以前的算法（比如查重率、关键词匹配度）。但大模型如果把“我赚了”回答成“我盈利了”，意思完全一样，但因为词不一样，旧打分算法会判定为错。

新方案（LLM 当裁判 / Ragas 框架）：我们雇佣一个更强的大模型（比如 Claude 3.5 或 GPT-4）当“改卷老师”，用标准的逻辑去给我们的系统打分。这就是目前行业里最标配的 Ragas 评估框架。

### 2. 📚 生动的比喻：大模型系统的“开卷考试”三步打分法

RAG 系统回答用户问题的过程，本质上就是一场“开卷考试”：

用户提问 $\rightarrow$ 考试题目。

系统去后台翻书，捞出几段话（检索 Context） $\rightarrow$ 考生在书里找到的参考页。

大模型结合捞出来的话，写出回答（LLM Output） $\rightarrow$ 考生在卷子上写下的答案。

“改卷老师”（Ragas 框架）会死死扣住以下 3 个最核心的物理维度进行打分：

#### 📐 维度一：Context Relevance（书找对了吗？）

大白话：考生翻开的那几页书，跟考试题目到底有没有关系？

惨剧场景：用户问“沪电股份买入成本是多少？”，系统在后台翻箱倒柜，最后翻出几段“比亚迪今天的股价是 250 元”。

打分逻辑：书找错了，哪怕大模型再聪明也只能交白卷。这个得分高，说明你的检索系统（Retriever）很精准。

#### 📐 维度二：Faithfulness（抄对了吗？有没有瞎编？）

大白话：考生的答案，是不是严格根据他翻开的那几页书写出来的？他有没有自己“脑补”和瞎编？（也就是防幻觉指标）

惨剧场景：书上明明写着“买入成本: 30 元”，大模型脑子一热，在答案里写了“买入成本: 50 元”。

打分逻辑：答案里写的东西，如果在参考书页里找不到，直接判为“撒谎/幻觉”。这个得分高，说明你的提示词控制（Prompt Engineering）做得很棒，模型很听话。

#### 📐 维度三：Answer Relevance（答非所问了吗？）

大白话：考生的答案，到底有没有真正解决用户的考试题目？

惨剧场景：用户问“我这只股票今天该不该卖？”，大模型啰里啰嗦写了 1000 字介绍这家公司是做什么的，但就是没回答“该不该卖”。

打分逻辑：回答字数再多，如果不切中要害，相关性得分就很低。

### 🎯 3. 技术面试现场：面试官要是问，你怎么通俗接招？

#### 🎙️ 核心追问：你怎么向客户和团队证明你的大模型系统（RAG）优化后确实变好了？

满分通俗回答：

“在我的项目优化和交付中，我从来不用‘感觉变好了’这种主观的话。我们有一套科学的**‘开卷考试评估机制’**。

我们把系统回答问题的过程当成开卷考试，通过引入 Ragas 自动化打分框架，让能力更强的大模型（比如 GPT-4）扮演‘监考老师’，每次系统改动后，自动跑一遍由 100 条真实业务提问组成的黄金数据集：

老师会先检查**‘参考资料找对了吗’**（也就是 Context Precision），用来评估我们的 RAG 检索器灵不灵；

再检查**‘有没有照着书抄、有没有自己瞎编’**（也就是 Faithfulness 忠实度），用来防范大模型的数字幻觉；

最后检查**‘有没有答非所问’**（也就是 Answer Relevance）。

我们每次修改 Prompt 或者更新检索因子后，都必须把这三个维度的得分稳定提升到 $90\%$ 以上才允许上线。这种用客观、量化数据说话的评估闭环，能够向甲方团队给出最踏实的工程交代。”
